# Sample / solution

## Why this approach works
Sorting by the verb, not by gut feel, is what makes this defensible. Every use case on the board contains a signal: predict, detect, assign, and cluster point to classic machine learning because the output is a number, a label, or a grouping derived from historical data. Draft, summarize, answer, and generate point to GenAI because the output is language produced for a reader. U6 is deliberately in between, and naming it as such is part of the lesson: a grounded GenAI answer and a classic retrieval or rules system can both do the job, and the safer choice depends on risk, not on fashion. When a placement is uncertain, the uncertainty usually means the use case is underspecified, which is a finding in itself.

## A complete solution
Take U6, "Answer questions from a fixed approved FAQ without inventing." A complete defense sounds like this: "I place U6 on the boundary. If we use GenAI, it must be grounded, answering only from the approved FAQ with an explicit 'not stated' fallback, because an ungrounded model will invent plausible-sounding policy. But the honest engineering answer is that classic retrieval or rules may be safer here: the FAQ is fixed, the answers are known, and there is an answer key to test against. I would only choose GenAI if residents ask in very varied natural language that a rules matcher keeps missing." That placement earns the point because it names the mechanism (grounding), the failure mode (invention), and the deciding factor (answer key availability). A weaker answer like "GenAI because it is a chatbot" gets challenged on exactly those three missing pieces. The other seven items sort cleanly: U1, U3, U5, U7 to classic ML; U2, U4, U8 to GenAI.
