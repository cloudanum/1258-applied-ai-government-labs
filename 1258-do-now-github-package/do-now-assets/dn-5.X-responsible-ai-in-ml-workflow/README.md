# Do Now 5.X: Responsible AI in ML Workflow 🎯

**Time:** 5 minutes
**Format:** No sandbox or tooling required, this activity is done mentally and captured directly on the Mural board (or in Zoom chat if you are remote).
**Mural:** https://app.mural.co/t/day10626/m/day10626/1790240802067/2c53eed9d5cc2bc1f1fb3241456b5a3f6422f003

## Goal
Attach one responsible-AI practice to each of the five classic ML workflow stages, define, prepare, build, evaluate, deploy, and give every practice a named owner using the template `step -> practice -> owner`. You also flag the one stage where, in your experience, nobody is ever accountable.

**Assets:** Workflow step stickies: define, prepare, build, evaluate, deploy (see `board-items.tsv`).

**🛡️ Real incident, MITRE ATLAS:** [ATLAS mitigations](https://atlas.mitre.org/mitigations). ATLAS pairs every attack technique with mitigations, and each mitigation implies the lifecycle stage where it belongs, from data preparation to deployment monitoring. Comparing that list with your workflow map shows which stages in your process currently carry no named mitigation and no owner.

**🧩 Pattern watch:** Design pattern, **Checkpoints in the lifecycle**: responsible-AI practices attached to stages with named owners. Anti-pattern, **Ethics as afterthought**: a review scheduled for the week after launch.

**🏛️ Framework link:** [OECD AI Principles](https://oecd.ai/en/ai-principles), The workflow checkpoints you mapped echo the OECD AI Principles, the intergovernmental standard most national AI strategies borrow from.

## Run steps 🪜
1. Open the Mural board linked above (or follow along in Zoom chat if the instructor is running it verbally).
2. Look at the five workflow-stage columns, **define**, **prepare**, **build**, **evaluate**, **deploy**, and recall what actually happens at each stage on a real project.
3. Place one responsible-AI practice sticky under each stage, e.g. de-identification and representative sampling under *prepare*, fairness and explainability review under *evaluate*, human-oversight sign-off under *deploy*.
4. Give every placement an owner as a Mural comment (or Zoom chat message) in the template `step -> practice -> owner`, e.g. `evaluate -> fairness review -> model risk lead`.
5. Flag the one stage where your agency typically names no owner, with a color tag or a one-line comment saying who *should* own it.
6. Initial or color-tag your placements before the instructor walks through a reference mapping.

## Key takeaway 💡
Responsible AI lives inside the workflow, not after it, every stage from define to deploy needs a named practice and a named owner, because unowned practices are the ones that quietly get skipped.

## Study further 📚
- [NIST AI Risk Management Framework, NIST](https://www.nist.gov/itl/ai-risk-management-framework), the U.S. government's reference framework for trustworthy AI across the system lifecycle.
- [AI RMF Playbook, NIST AI Resource Center](https://airc.nist.gov/AI_RMF_Knowledge_Base/Playbook), suggested actions mapped to the framework's Govern, Map, Measure, and Manage functions.
- [Artificial Intelligence: An Accountability Framework for Federal Agencies (GAO-21-519SP), GAO](https://www.gao.gov/products/gao-21-519sp), federal accountability practices organized around governance, data, performance, and monitoring.

## Common mistake to name ⚠️
Parking responsible AI at the end of the pipeline: privacy and representativeness decisions belong in define and prepare, long before any model exists.

## If finished early ⏩
Add a second practice for the stage you flagged as ownerless, and name the role, not just the team, that should own it.

## ⭐ Bonus (optional)
Pick one practice you placed and write down the artifact it should produce, a de-identification report, a fairness scorecard, a sign-off record. Practices without artifacts are indistinguishable from good intentions.
