# Sample / solution

## Why this approach works
Each part of the template kills a different way first projects die: the plain sentence keeps scope routine, the named user makes adoption someone's actual job, and the measurable result with a baseline turns the pilot into a claim leadership can verify. "Use AI to improve customer service" fails all three tests at once.

## A complete solution
The full chat post, in the capture format from the run steps:

`Use case: Draft first-pass responses to routine permit status questions. | User: Permit intake staff. | Measurable result: Median first-response time drops from 2 days to same day with no increase in corrections.`

Read aloud, the defense sounds like this: "The work is repetitive and text-shaped, permit status questions arrive daily with the same structure. The user is a named team that would touch the tool every day, not a vague org unit. And the result has a baseline, a target, and a guardrail metric, so we do not trade accuracy for speed and can defend the whole thing to a CIO in one sentence." A good one-line reply to a peer is "strong first use case, named user and a metric with a baseline; consider adding a guardrail metric like correction rate," while "AI to modernize our permitting program" earns the correction "not yet a use case, which routine task and which daily user would you start with?"
