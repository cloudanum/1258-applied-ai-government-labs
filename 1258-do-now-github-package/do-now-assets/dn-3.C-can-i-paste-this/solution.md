# Sample / solution

## Why this approach works
The paste decision turns on status, not just visible content: the three questions (who is in this, who is it for, what is its release status) catch what a name-scan misses. A label like "aggregated" or "synthetic" is a claim someone must confirm before the content is safe to paste.

## A complete solution
Full placement, and the chat line for remote participants: `C1-OK, C2-Never, C3-Never, C4-Mask, C5-Never, C6-OK, C7-Never, C8-Mask`. That is: OK bucket, C1 (public park-hours webpage text) and C6 (a published open data dictionary). Never bucket, C2 (a resident's name, phone number, and service address: direct identifiers), C3 (internal draft policy marked deliberative, not for release), C5 (an employee's performance feedback note), and C7 (a security incident timeline with system names and an exploited weakness). Mask first bucket, C4 (aggregated statistics: only safe once someone confirms the small-cell suppression rules were applied) and C8 (synthetic citizen records: only safe once someone confirms they carry no echo of real cases).

Take C3, the classic split. The defense: "Release status decides, not content. This draft is marked deliberative, not for release, so pasting it into an AI tool is an unreviewed release of pre-decisional material, and the absence of personal details changes nothing about that. If I need the same kind of help, I paste a cleared public policy instead, or I ask the structural question with no draft text at all." The policy question to check first, posted as the board comment: for C4, "who confirmed the small-cell suppression rules were applied to these statistics?" If you finish early, the masked rewrite of C2 is "a resident at a service address in Ward 3," which keeps the analytical value and drops every identifier.
