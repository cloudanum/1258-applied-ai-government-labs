# Sample / solution

## Why this approach works
The six-dimension checklist works because government data fails in boring, repeatable ways, and naming the dimension converts a vague "this looks off" into a category you can check systematically across millions of rows. Validity catches values that cannot exist (a month 13), uniqueness catches the duplicate that double-counts demand, completeness catches the blank that breaks a group-by, consistency catches the label that splits one category into two, accuracy catches the plausible-but-wrong value like latitude 999, and timeliness catches staleness. The weak instinct is to fix whatever you spot and move on; the discipline is to tag every dirty row with its dimension, because the tag tells you which validation rule would have caught it automatically. The exercise also teaches triage: the worst row is not the one with the most problems but the one whose problem is hardest to detect downstream.

## A complete solution
The full board, postable in chat, reads: `ROW2: consistency, 01/03/26 and "Ward five" (the blank status also fails completeness)`. `ROW3: validity, month 13 in 2026-13-03`. `ROW4: consistency, lowercase "pothole" splits the category`. `ROW5: uniqueness, request ID 311-10485 repeats ROW4`. `ROW6: completeness, ward is blank`. `ROW7: accuracy, latitude 999 is impossible`. `ROW8: validity, "Closed?" is not a standard status`. `ROW10: consistency, lowercase "ok"; plus validity, Ward 10 sits outside the expected range`. ROW1 and ROW9 are clean and take no tag.

Take ROW2. The wrong instinct is to treat "Ward five" versus "Ward 5" as cosmetic, a spelling nicety a person can read through. A complete defense sounds like this: "I tag ROW2 for consistency twice and completeness once. The date 01/03/26 does not match the ISO format used by the other rows, so a parser either rejects it or, worse, silently reads it as March 1 instead of January 3. 'Ward five' will not join to a ward lookup table or group with 'Ward 5,' so ward-level dashboards undercount Ward 5 by exactly the rows written out as words. And the blank status means this request vanishes from any open-versus-closed report." That is three downstream breaks from one short row, which is why "cosmetic" is the most expensive word in data quality.

For the worst-offender star, ROW7 is the defensible pick: a missing ward announces itself, but latitude 999 is a confident, wrong value that passes a completeness check and drops a city request into the ocean on every map until someone notices. ROW5 is the other strong candidate, since a duplicate request ID double-counts demand for the same pothole; either pick earns the point if the one-sentence defense names what breaks.
