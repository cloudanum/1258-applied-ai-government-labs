# Sample / solution

## Why this approach works
The three-bucket sort works because it forces the deciding questions out into the open: does this purpose need actual current patterns, does it touch personal data, and should it exist at all. Synthetic data earns its place when realistic volume or structure matters but real records are not yet approved or not needed, which is why the prototype, the classroom exercise, and the load test all land there. Real data is mandatory when the conclusions must describe the world as it is: a production fraud model and an equity audit both fail by definition if fed invented rows. The weak instinct is to treat synthetic as the privacy-safe default for everything; synthetic data can still leak patterns from its source, and it can never stand in for real outcomes in an audit. The hard-won lesson is the third bucket: "Neither" is a legitimate, sometimes mandatory, placement, and being able to say "do not build this" is part of data strategy.

## A complete solution
The six placements, postable in chat, read: `D1-Synthetic, D2-Real, D3-Synthetic, D4-Neither, D5-Synthetic, D6-Real`. D1 prototypes eligibility rules before any real data is approved, so synthetic first, with a planned switch to governed real data later. D3 teaches missing-value mechanics, so synthetic or sampled public data is enough. D5 needs realistic volume, not realistic people, so synthetic keeps personal data out of a load test. D2 predicts current fraud, which only real, current patterns can support. D6 audits a live system's actual outcomes, which no generator can fabricate.

Take D4, estimating a person's exact income from confidential tax records, and argue it against D2, because the two look alike and the disagreement is the teachable moment. The wrong instinct is "both are prediction on sensitive data, so both take real data." A complete defense sounds like this: "D2 and D4 differ in purpose, not technique. D2 serves a legitimate enforcement function and can be governed: legal authority, minimization, oversight. D4 infers an exact financial attribute about identifiable people from records that are confidential by law, and no data strategy, real, synthetic, or otherwise, makes that purpose acceptable. The placement is Neither: the deliverable is a refusal with reasons, not a dataset." For the privacy flag, mark D6: it is the right thing to do and still carries the heaviest privacy load, because auditing for equity requires real outcomes analyzed by protected class where lawful, so it demands explicit legal authority, minimum-necessary access, and tight controls on who can see the joined data.
