# Sample / solution

## Why this approach works
The three-bucket sort forces the deciding questions into the open: does this purpose need actual current patterns, does it touch personal data, and should it exist at all. Synthetic data earns its place when realistic volume or structure matters but real records are not approved or not needed; real data is mandatory when the conclusions must describe the world as it is.

## A complete solution
The six placements, postable in chat, read: `D1-Synthetic, D2-Real, D3-Synthetic, D4-Neither, D5-Synthetic, D6-Real`. D1 prototypes eligibility rules before any real data is approved, so synthetic first, with a planned switch to governed real data later. D3 teaches missing-value mechanics, so synthetic or sampled public data is enough. D5 needs realistic volume, not realistic people. D2 predicts current fraud, which only real, current patterns can support. D6 audits a live system's actual outcomes, which no generator can fabricate.

D4 looks like D2, and the disagreement is the teachable moment. A complete defense sounds like this: "D2 and D4 differ in purpose, not technique. D2 serves a legitimate enforcement function and can be governed: legal authority, minimization, oversight. D4 infers an exact financial attribute about identifiable people from records that are confidential by law, and no data strategy makes that purpose acceptable. The placement is Neither: the deliverable is a refusal with reasons, not a dataset." For the privacy flag, mark D6: auditing for equity requires real outcomes analyzed by protected class where lawful, so it demands explicit legal authority, minimum-necessary access, and tight controls on the joined data.
