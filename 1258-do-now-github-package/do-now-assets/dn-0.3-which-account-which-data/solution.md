# Sample / solution

## Why this approach works
The two questions, which account and which data, turn a gut-feel sort into a defensible one. Every scenario on the board passes or fails on those two axes alone: personal information or an unapproved personal account is an automatic No no matter how harmless the task feels, and a licensed account with public data is a different universe from a personal account with case files. The weaker instinct, sorting by how routine or how important the task sounds, fails on S4: drafting help feels innocent, but internal procurement strategy uploaded to a personal AI account fails both questions at once, and you should be able to name both. The Caution column earns its place for the cases where the paste itself is allowed but something still needs checking, the answer, the tenant settings, or the masking. Being able to say which axis a scenario fails on is the difference between a rule you can apply on Monday morning and a vibe you cannot defend in an incident review.

## A complete solution
S6 is the hardest call. A full defense sounds like this: "I place S6 in No as written, because production logs containing IP addresses and user IDs are personal and operational data going to an outside tool, and debugging convenience does not change what the data is. But I note the flip: mask the identifiers first, or run the same debugging inside an approved logging environment, and the scenario moves out of No. The tool was never the whole problem; the identifiers were." That placement earns the point because it names the failed axis (data), the failure mode (identifiers leaking to a third party), and the condition that changes the verdict (masking or an approved environment).

S5 is the other edge case: the account is right (agency-licensed, no training on agency data), so the only open question is configuration, which puts it at the Approved/Caution line until someone confirms the tenant settings. S1 sits at the same line from the other direction: the data is fully public, so Approved is defensible, but the answer still has to be verified before it goes back to the resident, which is why Caution is the safer habit. The full board: S1-Caution, S2-No, S3-Approved, S4-No, S5-Caution, S6-No until masked. Posted remotely: `S1-Caution, S2-No, S3-Approved, S4-No, S5-Caution, S6-No`.
