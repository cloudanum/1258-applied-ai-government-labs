# Sample / solution

## Why this approach works
Sorting by what happened to the data, was something exposed, something changed, or something unavailable, works because the triad is the shared vocabulary between AI teams and security teams, and once a failure maps to a leg, existing controls, owners, and incident processes apply. The discipline matters because AI failures do not arrive wearing labels: prompt injection arrives as ordinary text, and a silently changed benefit amount makes no headline at all. The weaker instinct is dumping everything into Confidentiality because breaches are what make the news; the failure mode that misses is an Integrity failure like F2, which can hurt residents more than a leak while never triggering anyone's incident playbook, because nobody named the leg and therefore nobody owned the fix. Flagging a failure that spans two legs is not indecision; it is how you learn that the legs interact, which is what incident response will discover the hard way if you do not.

## A complete solution
Full placement: Confidentiality gets F1 (citizen addresses emailed to the wrong list), F4 (training data on a contractor's personal laptop), and F8 (another person's medical detail in a records response), each one something exposed. Integrity gets F2 (benefit amount silently changed after a bad update), F5 (prompt injection rewriting the assistant's instructions), and F7 (source data edited so future reports are wrong), each one something changed. Availability gets F3 (chatbot down during an emergency declaration) and F6 (flood takes out the only hosting region), each one something unavailable when residents need it. Chat post: `C: F1, F4, F8 | I: F2, F5, F7 | A: F3, F6 | spans two: F5`.

F5 is the tricky one and the placement to defend out loud. The wrong instinct is to file it under Confidentiality because injections are associated with data leaks, or to dismiss it as a conversation problem because it arrives as text. The correct call is Integrity: the injection changes the assistant's instructions, and changed instructions are corrupted configuration, no different in kind from F2's changed benefit amount. It also genuinely spans two legs, and saying when is the real test: the moment the hijacked instructions make the assistant leak records, the same event becomes Confidentiality too, which is why one incident can need two owners. My one-sentence defense on the board: "F5 is Integrity because the injected text changes what the system is instructed to do; it only becomes Confidentiality if the changed instructions then expose records." Once the board agrees, the follow-on conversation writes itself: F3's owner is whoever owns continuity of operations, F2's owner is whoever owns update review, and naming the leg is what assigned them.
