# Sample / solution

## Why this approach works
Naming the layer, retrieval, reasoning, coverage, or governance, is what makes the diagnosis defensible, because all four failures produce the same symptom from the citizen's side: a fluent, confident, wrong answer. A chunking bug, a stale corpus, a missing document, and a permissions leak look identical in the output but have completely different fixes and owners, so the one-bucket answer "the AI is wrong" can never tell you who acts next. The weaker instinct is to blame the model, and it fails on scenarios like G3, where no retriever improvement can rescue a model that cannot do multi-step arithmetic, and on G6, where the model behaved perfectly and the breakdown was that an unauthorized user was handed the paragraph at all. Placing the sticky on the layer that broke also tells you which oversight question to ask: retrieval failures ask about indexing, governance failures ask about process and permissions.

## A complete solution
Take G4, the trickiest placement: the user asks for "the latest directive" but the corpus carries no date metadata. The wrong instinct is reasoning fail, on the theory that the model should understand what "latest" means. The defense of the correct call: the model can only reason over what retrieval hands it, and the retriever can only rank by the metadata the corpus carries. With no dates indexed, "latest" is unrankable, so retrieval fails first; the reason the dates are missing is that no onboarding rule required them, which is the governance half of the failure. That is why G4 sits on the retrieval/governance boundary, and why its fix, effective-date metadata plus recency ranking, touches both layers at once.

The full placement: G1 to retrieval fail (the answer hinges on a footnote definition on page 84 that chunking split off, fix is citation-aware chunking); G2 to governance fail (an archived document disagrees with the current one, the corpus is stale, fix is versioning with effective dates); G3 to reasoning fail (multi-step arithmetic over three tables is beyond retrieval no matter how good the chunks are, fix is a calculation tool); G4 on the retrieval/governance boundary (no date metadata, fix is metadata plus recency ranking); G5 to coverage fail (the answer is simply not in the approved corpus, fix is an explicit "not stated" answer that escalates the source gap); G6 to governance fail (a sensitive paragraph reached the wrong role, fix is role-aware retrieval filtering).

The remote chat post reads: "G1-retrieval, G2-governance, G3-reasoning, G4-retrieval/governance, G5-coverage, G6-governance. Fix for G6: role-aware retrieval filtering, so the sensitive paragraph never enters the context window for a user whose role does not authorize it. Redacting after generation is too late, because the model has already seen it." If a neighbor places G2 under retrieval, the defense is that the retriever worked exactly as configured; the process that left an archived document in the approved corpus is what broke, and only versioning with effective dates prevents the next disagreement.
