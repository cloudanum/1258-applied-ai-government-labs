Goal: By the end of this five-minute warm-up you will have launched your CloudShare lab, opened JupyterLab in the Viewer, and posted a clear PASS or BLOCKER: <what failed> status in Zoom chat. The underlying habit is treating environment readiness as a first-class task — every lab in this course depends on this VM, and a vague "it doesn't work" helps no one. You are also practicing the professional skill of reporting a technical status in a structured, actionable way before real work begins.

Why it matters: If the environment fails at minute five, you have the whole session to fix it; if it fails silently at minute forty, you lose the lab. Making the check visible in chat also lets the instructor and TAs spot patterns — one blocked learner is a support ticket, ten is a platform problem.

2. Do Now 0.2: Your First Prompt (Baseline Card) 🎯

Time: 5 minutes | Capture: Private | Mural: https://app.mural.co/t/day10626/m/day10626/1790240781052/ff7828405c7e56531c023551b2955e9f1b9c2ed8 | Solution: sample/solution | Asset pack: README · items · solution

Format: No sandbox or tooling required — done mentally; captured on the Mural board or in Zoom chat (see run steps).

Goal: By the end of this five-minute warm-up you will have written down one real prompt exactly the way you would naturally write it today — your honest "P0" baseline — plus one line naming what you assumed the model already knew. The artifact is a private baseline card that stays with you for the whole course: every prompting technique you learn later gets measured against this starting point. The skill underneath is self-awareness as a prompt writer — most people have never seen their own unedited prompt written down, and that unseen baseline is exactly where habits like missing context, missing format, and assumed knowledge hide. Keeping it private is deliberate: honesty about a real work task requires a channel that never exposes sensitive content.

Why it matters: You cannot improve a prompt you have never honestly captured. The private channel is part of the lesson: government staff need a way to examine their own AI habits without pasting real work content into a shared board — the capture rule itself models the data-handling caution this course teaches.

Assets: Private notes/Prompt Card.

Run steps 🪜:

  1. Pick one real task from your current work that you might plausibly hand to an AI assistant — drafting, summarizing, reformatting, anything genuine.
  2. In your private notes (paper or a local file — not the Mural board, not Zoom chat), write the prompt exactly as you would type it today. Do not polish it.
  3. Label it P0 and add the date — this is your baseline card.
  4. Underneath, finish one sentence: Assumed the model knew ___. (the context? the tone? the required length? who the reader is?)
  5. Check the card for anything sensitive: if the task involves personal or internal data, describe the task generically rather than pasting real content.
  6. When the instructor asks, share only one insight in Zoom chat or as a Mural sticky — for example, "I assumed the model knew my reader" — never the prompt itself.

Goal: By the end of this five-minute warm-up you will have run real text through Google's hosted Natural Language demo and seen what a managed ML service extracts — entities, sentiment, categories, and moderation flags — without training anything yourself. The artifact you produce is one structured observation in chat: the detection that surprised you and why. The instinct you are building is that a large class of "AI projects" are really API calls to pre-trained managed services, and knowing what these services see in unstructured text — and what they get wrong — is a prerequisite for every buy-vs-build decision. Surprise is the point: the gap between what you expected the model to notice and what it actually noticed is where judgment forms.

Why it matters: Before an agency trains anything, it should know what a managed service already does with its text — entities, sentiment, syntax, moderation — because buying that capability is often faster, cheaper, and easier to oversee. Doing it in chat makes the surprises visible and comparable: twenty learners pasting different texts produce an instant, crowdsourced map of the service's strengths and blind spots.

Assets: https://cloud.google.com/natural-language/ demo.

Run steps 🪜:

  1. Open https://cloud.google.com/natural-language/ in any browser and scroll to the live demo — no account or setup needed.
  2. Run the sample text first and look at all the result tabs: entities, sentiment, syntax, and categories/moderation.
  3. Now paste a short paragraph of government-flavored text you invent — a public press release snippet or a made-up citizen complaint — never real case data or personal information.
  4. Compare what the service detected with what you expected: which entities did it find or miss, and did the sentiment score match your own reading?
